# Coca-Cola Quiz Arena

واجهة عربية RTL لمسابقة صفية بين 10 أفواج، بتصميم Coca-Cola الأحمر والأسود وقارورة زجاجية متحركة.

## ما الذي تغير في هذه النسخة؟

- تحولت من تجربة محلية إلى عميل متعدد الأجهزة يعتمد على Supabase Edge Function.
- تنشأ رموز دخول عشوائية للأفواج العشرة ورمز منفصل للمنظّم عند التهيئة الأولى. تُخزّن بصيغ مشتقة PBKDF2 مع أملاح عشوائية، ولا تُخزّن الرموز الخام في قاعدة البيانات.
- يحتفظ الخادم بترتيب الضغط ويمنع تسجيل الفريق أكثر من مرة في السؤال نفسه.
- جميع الفرق تستطيع الضغط خلال نافذة الثماني ثواني التي تبدأ بعد انتهاء العدّ التنازلي (3 ثوانٍ). يبقى ترتيب الطابور محفوظًا حتى أثناء إجابة الفريق الحالي.
- لكل فريق دوره لمدة 5 ثوانٍ؛ يتحقق الخادم من هوية الفريق والدور والوقت والإجابة الصحيحة.
- الإجابة الصحيحة تضيف 10 نقاط وترفع امتلاء القارورة 5%. الخطأ أو انتهاء الوقت ينقل الدور إلى الفريق التالي.
- تتزامن الشاشات باستطلاع آمن للخادم كل 850 مللي ثانية تقريبًا. هذه مزامنة شبه فورية عبر polling وليست اشتراك Supabase Realtime.
- لا تُرسل الإجابة الصحيحة إلى المتصفح، كما أن جداول `arena_*` غير متاحة مباشرة للأدوار العامة.

## الملفات المهمة

- `index.html`, `styles.css`, `app.js`: واجهة المسابقة.
- `config.js`: عنوان مشروع Supabase والمفتاح العام فقط.
- `supabase/migrations/001_arena_core.sql`: جداول ودوال قاعدة البيانات الجديدة.
- `supabase/functions/arena/index.ts`: وظيفة الخادم التي تصادق المستخدمين وتنفذ عمليات المسابقة.
- `supabase/config.toml`: تعطيل تحقق JWT الافتراضي للوظيفة لأن الوظيفة تتحقق من رمز الجلسة الموقّع الخاص بالمسابقة بنفسها.

## إعداد Supabase — نفّذ هذا مرة واحدة

> لا تعِد تشغيل `supabase/schema.sql` القديم. لا تحذف الجداول الأربعة الموجودة لديك. ملف الترحيل الجديد يستخدم أسماء `arena_*` مستقلة ولا يغيّرها.

1. افتح مشروع Supabase ثم **SQL Editor → New query**.
2. انسخ كامل محتوى `supabase/migrations/001_arena_core.sql` والصقه ثم اضغط **Run**. يجب أن تظهر رسالة نجاح.
3. افتح **Edge Functions** وأنشئ Function باسم `arena`.
4. انسخ محتوى `supabase/functions/arena/index.ts` كاملًا إلى محرر الوظيفة ثم انشرها (**Deploy**). استخدم إعداد `verify_jwt = false` من `supabase/config.toml` عند النشر؛ فالوظيفة تتحقق بنفسها من رمز الجلسة.
5. افتح **Edge Function Secrets** وأضف:
   - `ARENA_TOKEN_SECRET`: سلسلة عشوائية طويلة لا تقل عن 32 حرفًا.
   - `ARENA_SETUP_KEY`: رمز تهيئة عشوائيًا طويلًا تحتفظ به سرًا.
   - يجب أن تكون أسرار Supabase الافتراضية `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` متاحة للوظيفة. لا تضع مفتاح الخدمة في `config.js` أو داخل المتصفح.
6. افتح الموقع، ثم **دخول المنظّم → تهيئة المسابقة لأول مرة**، وأدخل قيمة `ARENA_SETUP_KEY` نفسها واضغط **إنشاء المسابقة ورموز الأفواج**.
7. ستظهر رموز عشوائية للمنظّم والأفواج العشرة مرة واحدة. انسخها واحفظها قبل مغادرة الصفحة؛ وزّع رمز كل فوج على فريقه، ولا تشارك رمز المنظّم.
8. بعد ذلك يستخدم المنظّم رمز المنظّم للدخول، وتدخل الفرق من هواتفها باستخدام رقم الفوج ورمزه.

## نشر الواجهة

ارفع ملفات جذر المشروع (`index.html`, `styles.css`, `app.js`, `config.js`) إلى جذر مستودع GitHub، ثم فعّل GitHub Pages من Settings → Pages واختر الفرع `main` والمجلد `/(root)`.

## ملاحظات أمنية وتشغيلية

- `config.js` يحتوي على مفتاح النشر العام فقط. لا تضف إليه `service_role` أو `sb_secret_` أو كلمات مرور قاعدة البيانات.
- جداول `arena_*` محمية بـ RLS ولا تمنح صلاحيات قراءة/كتابة مباشرة لـ `anon` أو `authenticated`. كل التغييرات تمر عبر Edge Function بمفتاح الخدمة الموجود في الخادم.
- رموز الفريق والخادم تُشتق باستخدام PBKDF2-SHA256، وجلسات المسابقة موقعة وتنتهي بعد 8 ساعات.
- بعد التهيئة الأولى لا يمكن تشغيل `bootstrap` مرة ثانية على المسابقة نفسها. لا تمسح الجداول لإعادة التهيئة.
- لا يمكن اعتبار النظام جاهزًا للاستخدام الفعلي قبل تنفيذ خطوات النشر أعلاه واختبار الدخول من عدة هواتف واتصال الشبكة.
- توجد نافذة ضغط مدتها 8 ثوانٍ بعد العد التنازلي. إذا لم يضغط أي فريق خلال النافذة، تُغلق الجولة دون إجابة.
